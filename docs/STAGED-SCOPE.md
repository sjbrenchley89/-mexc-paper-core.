# Staged scope and verification boundaries

The user asked for a staged, non-coder walkthrough and expressly deferred the dashboard and optional modules until earlier steps are completed. Stage 1 supplies the independently runnable paper core. It does not claim to be the complete automatic live-trading system.

Stage 1: standard-library Python CLI; transactionally persisted SQLite paper ledger; exactly two built-in strategies; Option A default and Option B selectable; approved-list public scanner; local-only webhook; supplied, uncompiled Pine template; fees and slippage; ATR sizing; persistent daily halt and review; hard paper floor; immutable maximum allocation limits; closed-candle backtest paths.

Stage 2, pending earlier-stage completion: authenticate to MEXC with trade-only credentials, current account/symbol schema verification, real whole-account valuation, independent paper/live ledgers, fills/partial-fill tracking, reservations and client order IDs, uncertain-submission reconciliation, protective order behavior, restart preflight, and explicit user-controlled live activation. The current core must not be reused as a live executor without this work. The SQLite ledger currently represents only simulated funds, not the real MEXC account.

Stage 3, pending CLI usability: authenticated private web dashboard calling the same control service; no public trading controls or exchange keys in browser state.

Second installment (delivered): manual news veto that blocks entries only; copy-signal slot with disconnected FOMO and Astral adapters, a manual relay command and a per-provider report; AUD record CSV with Australian tax-year labels. Still pending below: an automatic news feed and any connected copy feed.

Third installment (delivered, unverified against MEXC): market-data fixes to match the published API (60m candles, rules from baseSizePrecision and quoteAmountPrecision, scanner units); signed MEXC client; live ledger with durable order intents, reservations, client order IDs, settlement from exchange records, uncertain-order reconciliation, whole-account sync and halts, exit back-off, single-process lock; go-live preflight with hard paper-trial gates; typed live confirmation. Not delivered: exchange-side stop orders, any run against the real exchange, dashboard.

Optional modules: provider-permitted FOMO/Astral feed adapters with durable source event IDs and latency/performance attribution; separately accepted Tradovate futures module that can reject every contract under the $10 notional ceiling; explicit portal rule import with validation evidence; chosen news provider with provider-specific reproducible rules and historical data. Each is disabled and unimplemented in stage 1; toggles deliberately refuse startup instead of implying integration exists.

Known limits: no successful current official-source lookup; no full referenced-thread retrieval; no allowed MEXC destination in this cloud network; no TradingView Pine compilation or delivered alert here. Required exchange symbol filters are fail-closed if absent or different from the supported schema. Indicator seeds can differ from TradingView. Simulated entries use current ticker, not measured bid/ask fills. Backtests do not reconstruct historical liquidity or historical minimum-order rules; low-first intrabar simulation is pessimistic. USDT is treated as USD-equivalent; a real USD floor requires valuation/depeg handling. Acquisition-cost caps and periodic marked exposure checks cannot guarantee instantaneous dollar exposure during price gaps. Local paper stops require a running process and current prices.

Webhook acceptance means queued, not filled. The queue is persisted without the token, but a crash after dequeue can drop an alert; paper mode errs toward missing an entry, never retrying an uncertain real order. A later live queue needs durable lifecycle states and reconciliation. Unique handled signal IDs and audit events are retained without truncation, so a long-running deployment needs storage monitoring. No claim of production readiness or profitability is made.
